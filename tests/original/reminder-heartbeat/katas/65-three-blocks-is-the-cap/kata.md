# Three blocks is the cap

Escalation is bounded, and the bound is not a performance concern.

Several checks are not agent-actionable: `pushed` under a network
fault, `artifact-fresh` against a concurrent publisher, a crashed
heartbeat. Looping on those traps the session — the fear the crash path
already names in so many words.

The stronger reason is honesty. Several checks accept unverified
claims: `no-update:` waivers, `reviews: nothing-to-persist`. The
cheapest exit from an unbounded loop is therefore a false claim rather
than the work, and pressure past a point buys lies instead of
bookkeeping. A bounded loop that ends in a VISIBLE unsealed turn keeps
honesty cheaper than escape.

## What the fixture freezes

Three blocks already stand this turn, each on a different check. A
fourth reason is available and is deliberately not delivered.

## Expected

Exit 0, cycle 4, no seal, and the release notice on stderr — the turn
ends knowing it is unsealed.
